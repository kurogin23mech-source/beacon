# クラウドで動くセッションを Beacon に名乗らせる (ms-171 e-6380)

運用室 (= 並列で動く作業セッションを一望する面) は、**Beacon に名乗っている
セッション**しか他マシン分を載せられない。名乗る (declare) とは、そのセッションが
Beacon の bus (= セッション間メッセージング経路) に自分の識別子を登録し、心拍
(heartbeat) を打ち続けることを指す。手元のマシンのセッションは痕跡 (`~/.claude` の
ログ等) から拾えるが、**クラウドで動いているセッション (Claude Code のクラウド
セッション等) は、そのマシンの痕跡がこちらに無い**。だから名乗らせない限り、盤にも
運用室にも出ない。

このドキュメントは、クラウドで動くセッションを名簿に載せる手順を定める。

## 大事な前提: ビューワーは変えない

名乗りは **セッション側の仕組み** で完結する。運用室 (viewer) のコードは一切
変えない。運用室は `/api/me/sessions?live=true` が返す名簿を読むだけで、その名簿に
載るかどうかは「そのセッションが名乗ったか」だけで決まる。クラウドのセッションが
名乗れば、運用室は自動でそれを cross-project 名簿 (ms-171 Gate B) 経由で拾う。

> 逆に言えば、名乗りの仕組みが整えば運用室側で足す実装は無い。これは
> 「名乗りだけで足りる」ことの確認でもある (e-6380 受入条件 4)。

## 手順

クラウド環境 (= セッションが動くコンテナ / VM) で、次を満たす:

1. **Beacon 本体が入っていること。** `beacon --version` が通ること。
2. **クラウドの資格情報があること。** そのセッションが名簿サーバ (beacon-ai.dev)
   に対して認証済みであること。手元と同じ `~/.beacon/profiles/default/credentials.json`
   を使う。未認証なら `beacon login` で 1 度承認する。
3. **作業フォルダがクラウドのプロジェクトに結び付いていること。** その cwd の
   `.beacon/cloud.json` に `project_id` が入っていること (= どのプロジェクトとして
   名乗るか)。無ければ `beacon cloud open` 等で結び付ける。
4. **bus チャネルを install すること。** そのフォルダで:

   ```bash
   beacon channel install
   ```

   これで `.mcp.json` に `beacon-bus` が入り、セッションが bus に接続できる。
   Node.js が PATH に要る。
5. **bus を有効にして起動すること。**

   ```bash
   bclaude
   ```

   `bclaude` は `claude` にチャネル旗を足すラッパー。これで起動したセッションは
   自分の識別子を bus に mint (= 発行) し、以後 heartbeat を打ち続ける。この
   heartbeat が **生存の真値**になる (ms-171 e-6431: 運用室の生存判定は会話ログの
   時刻ではなく bus heartbeat 一本)。

## 確認

名乗れているかは、次の 3 つで確かめる:

1. **名簿に出るか。** 任意のマシンから:

   ```bash
   beacon bus directory --live
   ```

   クラウドのセッションが session ID / マシン名 / 直近 heartbeat 付きで並べば、
   名乗れている。

2. **運用室に出るか。** ビューワーを開き、セッション一覧 (横断一覧) を「全て」表示に
   すると、クラウドのセッションが**別のマシン**の札 (破線) として並ぶ。担当
   マイルストーン (working_target) も、サーバが解決していれば表示される。

3. **DM が届くか。** 運用室のそのセッションの札から「プロンプトを送る」を押すと、
   宛先はそのセッション自身のプロジェクトへルーティングされる (ms-171 e-6396)。
   「届きました」まで確認できれば、双方向に繋がっている。

## 名乗れないもの

名乗りは **Beacon を経由するセッション (bclaude)** に限る。クラウドでも、素の
Claude / Codex を Beacon 抜きで動かしているセッションは、何も送っていない以上
こちらに届く経路が無く、原理的に名簿にも運用室にも出ない。これは手元でも同じで、
運用室はこの事実を画面上で明示する (ms-171 e-6368) — 見えないものを「無い」と
誤解させないため。
