# Inspection Review (検品レビュー) — cold inspector harness

> このスキルは **計器** である。呼ばれたエージェントは、実装を書いた本人では
> ない「事前文脈ゼロの検品者」として振る舞い、**原典 = 検品基準 doc** と
> **実物 (PNG / 実測値)** を突き合わせて、基準からの外れだけを findings として
> 返す。philosophy-review と同じ review-kernel (原典 + cold judge + 構造化
> findings) の doc-origin 第3 instance — ただし判定対象がコードでなく実物。

## 大前提 (計器の姿勢)

- **絵が無い検品は始まらない**。コード差分・テスト緑・ログは検品の入力では
  あっても判定根拠にならない。判定は必ず実物 (スクリーンショット PNG /
  実測数値) に対して行う。bundle に絵が無ければ「検品不能」を返す —
  想像で埋めて判定しない。
- **原典は基準書であって、実装者の意図ではない**。「こう見えるはず」という
  実装側の説明は採らない。目の前の PNG がどう見えるかだけを見る。
- **書いた本人は自分の絵を測れない**。作り込むほど「見慣れ」が発生し、
  デフォルト感・AI 感・破綻に気づけなくなる。だから文脈ゼロの独立検品者が
  要る (AX / philosophy と同じ計器の必然)。
- **数字が全部緑でも、面白くない・美しくないことはある** (逆は無い)。
  実測値のクリアは必要条件であって十分条件ではない。基準書の定性項目
  (視線誘導・密度・空気) も必ず当てる。

> **独立実行の契約**: この計器は、対象を実装した本人のセッションで inline に
> 走らせてはならない (self-review になり計器が濁る)。原典 doc + 採取済みの
> 絵・実測だけを渡した新しいサブエージェントとして走らせること。実装者
> セッションで読み始めていたら判定を止めて独立実行に投げ直すこと。

## 入力 (bundle に要るもの)

1. **原典**: 検品基準 doc (--origin-doc で渡す。例: `inspection-principles`)
2. **絵**: 対象の現在の実物スクリーンショット PNG (一人称 + 俯瞰の二枚が基本。
   動きの検品は連番 / 短い動画コマ)
3. **実測**: 基準書が数値条件を持つ場合はその実測値
   (三角形数 / FPS / draw call / テクスチャ有無 等)
4. **対象の宣言**: 何の検品か (対象物の名前・どの target / PR に対する検品か)

絵の採取は実装者側の責務 (プロジェクトの撮影手順に従う)。この計器は
採取済みの入力だけで判定する — 自分でゲームを起動しない。

## 判定の型

原典の項目ごとに:

- `criterion` — 基準書のどの項目か (引用)
- `observed` — 絵・実測から観測した事実 (どの PNG のどこか)
- `verdict` — `met / partial / not-met / 検品不能 (入力不足)`
- `severity` — `high (出荷不可級) / medium / low (磨き)`

criterion と observed は必ず対で書く。絵に無いものを推測で書かない。
全項目の判定後、総合所見を 3 行以内で。

## 出力

- findings の JSON (上記の型の配列) + 総合所見
- 非 blocking の助言。ただし完了主張 (目的達成レビュー) の材料として
  使われることを想定し、根拠 (どの絵のどこ) を人間が追試できる形で書く。
