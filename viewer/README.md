# Beacon 盤ビューワー

Beacon の盤 (= マイルストーンや進捗、誰が何を進めているかといった全体像) を
**実行ファイル 1 つで**見るための道具です。

**Beacon が入っていない PC でも見られます。** Python も beacon 本体も要りません。

## 使う

実行ファイルを置いて、動かすだけです。

```
beacon-view
```

ブラウザが開いて盤が出ます。起動した場所から上へさかのぼって `.beacon` を探すので、
プロジェクトの中ならどこで動かしても見つかります。見つからなければ、画面から
場所を選ぶか、クラウドにログインして選べます。

### 場所を指定して開く

```
beacon-view --path <Beacon プロジェクトの場所>
```

`.beacon` フォルダそのものでも、それを含むフォルダでも構いません。

### クラウドのプロジェクトを見る

画面の「クラウドから開く」からログインします。ブラウザで承認すると、参加している
プロジェクトの一覧が出ます。

クラウドに繋ぐと **他のマシンで動いているセッションも見えます**。誰がどの対象を
進めているかが、一覧の担当欄にも出ます。

認証情報は beacon 本体と同じ場所に保存するので、beacon が入っていて既にログイン
済みの PC では、そのまま使えます。

### そのほかの指定

| 指定 | 意味 |
|---|---|
| `--no-open` | ブラウザを自動で開かない |
| `--port 8080` | 待ち受ける口を指定する (塞がっていれば空きを借ります) |
| `--json` | 画面を出さず、盤の中身をそのまま出力する |
| `--host 0.0.0.0 --expose` | 自分の機械の外にも開く (下記) |

## サーバに置いて、ブラウザから見る

```
beacon-view --host 0.0.0.0 --port 8080 --expose
```

**`--expose` が必要なのは意図的です。** 盤にはプロジェクトの全体像が載るのに対し、
この受け口は認証を持ちません。外に開くことは、その口に届く全員に盤を見せることと
同じです。指定が無ければ起動せずに断ります。

社外に出す場合は、**認証を持つ前段 (reverse proxy 等) の後ろに置いてください。**

## 見えるセッションの 2 種類

画面では 2 つを分けて出しています。**届く範囲が根本的に違う**ためです。

| | Beacon に名乗っているセッション | このマシンで動いているセッション |
|---|---|---|
| どこから見えるか | **どのマシンからでも** | **このマシンの上だけ** |
| 分かること | 担当対象 / ブランチ / 直近コミット / 稼働状態 | 作業フォルダ / 最終活動時刻 / 起動中か |
| 対象 | bclaude 等、Beacon に参加しているもの | OpenCode / Claude Code / Codex など |

後者は、他のマシンの分は見えません。何も送っていないため、届く経路が存在しないから
です。画面にもその旨を出しています。

## 読み取り専用

このビューワーは **Beacon のデータも、他の道具のデータも、一切書き換えません**。

ただし SQLite を読むと `-wal` / `-shm` という補助ファイルが隣に作られます。これは
SQLite が読み手にも作るもので、中身は変わりません。作らない開き方もありますが、
その場合まだ反映されていない最新の変更が見えず、黙って古い盤を表示することになる
ため、そちらは採っていません。

## 組み立てる

```
./build.sh          # 全 OS 向けを dist/ に作る
./build.sh windows  # 1 つだけ作る
```

必要なのは Go だけです。C の道具立ては要りません (SQLite も純 Go の実装を使って
いるため)。Windows / macOS / Linux の amd64 と arm64、計 6 種類ができます。
1 ファイルあたり 11〜12 MB です。

開発中に手元で動かすだけなら:

```
go build -o viewer.exe ./... && ./viewer.exe
```

## 中身

| ファイル | 役割 |
|---|---|
| `project.go` | ローカルの `.beacon` を読む (SQLite / 旧 JSON の両方) |
| `cloud.go` | クラウドに繋いで読む (ログイン / プロジェクト一覧 / セッション名簿) |
| `board.go` | 読んだものを**表示用の共通の形**に変換する |
| `detail.go` | 対象 1 件の掘り下げ (画面で開いたときだけ取りに行く) |
| `local_sessions.go` | このマシンで動いているセッションの観測 |
| `server.go` | 画面と中身を配る |
| `page.html` | 画面 (実行ファイルに埋め込まれます) |

**表示用の共通の形**は Python 側の実装 (`lib/view_model.py`) と同じもので、
両者がずれていないことを `tests/test_go_viewer_parity_ms170.py` で確かめ続けて
います。二重に持つことを選んだ以上、これが唯一の歯止めになります。
